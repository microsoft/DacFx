# Release Notes

## Microsoft.SqlServer.DacFx 170.6.28-preview

This update brings the below changes over the previous release:

### Adds
* Adds options for exporting Azure SQL Database-compatible BACPAC files by excluding unsupported objects and their required dependencies, preventing exclusions that would lose table data, and optionally generating a JSON compatibility report.
* Adds support for SQL project references when comparing or publishing projects, preventing referenced objects from appearing as incorrect differences. [#437](https://github.com/microsoft/DacFx/issues/437)
* Adds support for SQLCMD variable values when comparing or publishing projects, preventing variable-based cross-database references from appearing as incorrect differences. [microsoft/vscode-mssql#21080](https://github.com/microsoft/vscode-mssql/issues/21080)
* Adds `PrePlanScript` handling for deployment script generation, with `RunAndRollback` and `RunOnce` modes to control whether pre-plan changes are reverted or retained.
* Adds public deployment history and fast comparison options.

### Fixed
* Fixes Fabric SQL Database and Fabric Warehouse projects that reference `master.dacpac` so system objects resolve correctly during build, Schema Compare, and deployment. [#850](https://github.com/microsoft/DacFx/issues/850)
* Fixes refactor-log renames and schema moves on Fabric SQL Database and Fabric Warehouse so deployments preserve existing objects and data instead of generating drop-and-create operations.
* Fixes Fabric Warehouse deployments for unsupported column changes by rebuilding tables when allowed, preserving dependencies, and honoring table recreation and data-loss settings.
* Fixes Fabric Warehouse table rebuilds that add non-nullable columns with default values so generated scripts populate the values without unsupported temporary constraints.
* Fixes data-phase index settings so saved deployment and Schema Compare configurations retain their values when reloaded. [microsoft/vscode-mssql#19185](https://github.com/microsoft/vscode-mssql/issues/19185)
* Fixes Schema Compare project updates when different object types share a name so each generated script is preserved. [#830](https://github.com/microsoft/DacFx/issues/830)
* Fixes scoped deployments that use refactor-log renames by loading renamed objects and reporting name collisions instead of producing invalid or incomplete deployment plans.
* Fixes fallback size estimation for large-object columns during BACPAC export.
* Fixes deployment scripts that use the sqlcmd `:connect` directive so transient connection failures use the standard retry behavior.

### Changed
* Reduces memory usage when extracting databases with large schemas.
* Updates `Microsoft.SqlServer.TransactSql.ScriptDom` from 180.117.0 to 180.140.0.
